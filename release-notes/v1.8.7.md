## 🔧 v1.8.7 Patch — Nvidia - VIctory Based

- **🎮 Launch uses your game folder** — `play-victory.cmd` no longer stops with "Set VICTORY_GAME_DIR to your own dump folder". The launcher passes the Game Folder from Settings (`VICTORY_GAME_DIR`) together with your Launch Options, the cache folder and the no-watchdog default. If the script cannot be used (the game exe is not `game_scarlett_master.exe`, or the runner has no release build), the launcher starts the runner it built itself, with the same settings.
- **🛠 Windows 10 build fix (LNK1169 / LNK2005)** — `D3D12SDKVersion` and `D3D12SDKPath` are no longer defined twice. The launcher links its own Agility SDK exports only when the runner's source does not define them, and builds again without them if the linker still reports duplicates.
- **📦 Runner's own D3D12 runtime** — a runner that exports its own `D3D12SDKVersion` (e.g. 614) keeps its own `D3D12\` runtime (the launcher runs its `get-d3d12`); the launcher's 1.620.2 is only installed next to an exe that exports 620. The runtime is also copied to `target\release` for the DLSS button.
- **⚡ "Build or Launch with DLSS"**
  - The download percentage of `Get-NVIDIA-DLSS.cmd` now shows in the log while it runs.
  - Its input is closed, so the script's final `pause` returns at once. The download is skipped when the DLSS files are already there.
  - New **Mode** button (Auto, 1–6, Menu): the chosen mode is passed as `PLAY_FRAMEGEN.cmd <mode>`, so nothing waits for a key. Auto picks mode 2 on RTX 20/30 cards (no DLSS frame generation there), mode 1 otherwise.
  - The log says that the first start builds a release copy of the runner and can take several minutes, and hints at mode 2 on RTX 20/30 cards.
  - The game folder from Settings is written to `game_dir.txt` for the script, so it does not search every drive.
